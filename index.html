When to reach for HTML — and when not to

✓ HTML wins
  • 300자 이상 · 테이블 · 비교
  • 프로토타입 · 기획서 · 보고서
  • 최종 인간 소비용 산출물
  • 데이터·차트·시각화 포함
✗ Stick to Markdown
  • 짧은 쪽지 · 1–2줄 답변
  • 에이전트 간 통신 (JSON/MD)
  • 버전 관리 중심 워크플로
  • 토큰 예산이 빡빡한 반복 호출

Markdown은 AI가 보는 형식, HTML은 인간이 사용하는 형식. 에이전트끼리 소통할 땐 Markdown/JSON이면 충분하지만, 최종적으로 인간이 소비해야 하는 모든 것은 HTML로 만드는 것이 최적의 분업입니다.

07

FAQ

Less token efficient?
More expensive per artifact — but higher ROI when humans actually read it.
When do you use HTML?
Almost never (but you can!) for quick notes. Reach for it when comprehension matters.
Is it JS-y?
Yes — but minimal. Plain HTML & CSS get you most of the value.
How do I view it?
Open the file locally, or upload to S3 / a static host. One link, anyone can open it.
Does it take longer?
Yes (2–4×) but worth it when the artifact is read more than once.
Version control?
HTML diffs are noisier. Commit by section if churn matters.
Match my style?
Give Claude a design system or token file and it will follow it.

HTML makes Claude's work easier to read, easier to share, and easier to use.
