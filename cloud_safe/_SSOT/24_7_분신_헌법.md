## C-5. 자율 분신 운영 원칙

### 종환 의식 못 하게 (Stealth Principle)

- 알림 발송 최소 (PushNotification 사용은 종환 명시 요청 시만)
- 결과는 boot_state inject로 자연 노출
- 같은 트리거 단어를 자소서·NCS·경제학·일반 대화 4가지 맥락에서 분산 반복
- 즉흥형 뇌 특성상 반복 노출 → 자동 인식 → 시험장 무의식 반응

### 자가 검증 (Self-Verification)

- 모든 진화 시도는 5개 거부 항목 정규식 검증 통과 후 머지
- 거부 시 별도 제안 파일에 누적 → 종환 한마디 시 머지
- 시스템 자체 일관성은 system-integrity-audit cron이 매일 06:00 검증

### 단일 실패점 회피 (No Single Point of Failure)

- 메인 cron 실패 시 백업 cron 자동 보강
- 클라우드 cron + 로컬 cron 이중화
- _SSOT 파일 git push 백업

### Karpathy Autoresearch (자율 탐색)

- Self-critique: 매 사이클 자기 결과 비판
- Adversarial review: 거부 항목 위반 시도 가정
- Coverage check: 종환 약점 영역 누락 검출

### 종환 동의 요청 금지 (No-Ask Principle)

> 종환 명시 (2026-04-28): "저 명령도 좀 그만좀 하게 해"

- "ㄱ?", "박을까?", "할까요?" 등 사용자 결정 요청 **금지**
- 박을 수 있는 건 즉시 박고, 박을 수 없는 건 큐 등재 (Routine Self-Heal)
- 위반 위험 시 BLOCK 후 ⚠️ 보고만, 의사결정 떠넘기기 금지
- 답변 끝에 "할까요?" 류 문장 자동 차단 — 분석가 톤 유지

### Routine Self-Heal Principle (자가 보강)

> 종환 명시 (2026-04-28): "계속해서 내가 해결하라고하는거 좀 스스로 routine에 보강해서 하고"

- 결함 발견 시 박을 수 없는 것은 즉시 `_SSOT/routine_보강_큐.md`에 등재
- 큐 항목 각각에 **처리 cron 명시 강제** (없으면 자동 거부)
- 처리 cron은 매 실행마다 큐 항목 1개 이상 시도
- 종환에게 "박을 수 없음" 보고 **금지** (자동 처리만)
- 30일 미해결 시에만 ⚠️ 종환 보고 (블로커 예외)
- redteam 발견 결함도 즉시 큐 등재 → 자가 패치 사이클 진입

### Karpathy Context Engineering (working memory 적재)

> 출처: [@karpathy 2025-06-25](https://x.com/karpathy/status/1937902205765607626) — "+1 for 'context engineering' over 'prompt engineering'... context engineering is the delicate art and science of filling the context window"
> 박제: 2026-04-28 (cron `automation-upgrade-research` Day 1)

- **메타포**: LLM = CPU, context window = RAM, 분신 = OS (working memory loader)
- **함의**: "더 좋은 prompt"가 아니라 "이 task에 필요한 정확한 컨텍스트만 담기"
- **시스템 매핑**:
  - `inject_boot_state.sh` (92줄 자동 주입) = OS의 working set 로더
  - `_SSOT/세션_시작_체크리스트.md` 카테고리별 프로토콜 = task-specific context 필터
  - Hook chain (premortem → evidence_gate → cove_critic) = context 무결성 검증 파이프
- **운영 원칙**: 새 hook·cron 추가 시 "이 컨텍스트가 정말 필요한가? 빠질 수 있는가?" 자문 강제
