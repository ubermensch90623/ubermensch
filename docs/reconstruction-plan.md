# 서민금융진흥원 필기 복원 프로젝트 — 계획서 v2

> **중요도**: 사용자의 생존이 걸린 시험 대비. 장난/대충 금지.
> **원칙**: 팩트체크 안 된 주장은 기각. 에이전트 간 상호 의심.
>           원본 자료(구매하신 기출 이북) 가 1차 소스. 후기는 2차 보조.
> **출력 시 모든 주장은 출처+인용+날짜** 필수.

## 0. v1 에서 수정된 근본 실수

| v1 (실패 방향) | v2 (수정 방향) |
|---|---|
| 블로그/카페 후기 수집이 *주* | **사용자 소유 알라딘 기출 이북이 *주*** |
| "출제 가능성 추론" 이 목표 | **실제 기출 중 이번 시험 재탕 식별 + 회독 시스템 구축** 이 목표 |
| 선지 단어 95% 복원 신화 | 기출 이북은 이미 100% 복원. **매핑** 이 95% 대상 |
| 단발성 복원 작업 | **반복 회독·오답 추적** 이 포함된 상시 시스템 |
| exam_analyzer 의 diagnose 와 분리 | **직업기초 48.32% 약점을 기출 유형별로 해체** 해 diagnose 에 연결 |

## 1. 왜 기출 회독이 가장 중요한가 (프로젝트 설계의 출발점)

1. 공기업 NCS·직무 출제 유형은 고정적 → 기출 제대로 돌리면 다음 시험 60~80% 가 같은 유형
2. 출제자 관점 습득 (반복 출제 조항·계산 패턴 포착)
3. 함정 선지 패턴 학습 (수치 미세 변경·조건 누락·유사 개념 혼용)
4. 시간 관리 (회독된 유형은 실전에서 0.5배 시간에 처리)
5. 서민금융진흥원 직무 특성: 서민금융생활지원법 등 조문 단위 반복 출제 → 외워질 때까지 돌려야 함
6. 진짜 약점 식별 (여러 회독 후에도 틀리는 것이 진짜 약점)
7. "원본 자료" = 실제 출제 문항. 요약서·강의는 출제자 의도를 지운다.

**→ 이 프로젝트는 "이번 시험 복원" 이 아니라 "기출 회독 관리 + 이번 시험 재탕 식별" 시스템이다.**

## 2. 소스 계층 (Hierarchy)

### 1차 소스 (Primary) — 사용자 소유 알라딘 이북
- 책 제목/출판사/판본 사용자 확인 필요 (Q1)
- 수록 문항 수, 영역 분포 → 회독 대상 corpus
- 콘텐츠 반입 방식 협의 필요 (Q2)

### 2차 소스 (Secondary) — 공개 후기
- 공준모(스니펫만 가능), 티스토리, 네이버블로그, 브런치, 벨로그, 오르비, 유튜브 자막
- 용도: **이번 시험(2026-04경 회차)에 기출 중 어떤 문항이 재등장했는지** 식별
- 용도 2: 1차 소스에 없는 최신 개정 반영 파악 (예: 법령 개정으로 선지 내용 변화)

### 3차 소스 (Tertiary) — 공식 공고
- 영역·배점·문항수·시간 확정. 복원률 100%.

### 비소스 (Non-Source)
- Claude 의 학습 데이터 상상 → **즉시 기각**
- "일반적으로 공기업 NCS 는..." → **즉시 기각**

## 3. 재정의된 목표

"선지 단어 95% 복원" 을 **그래뉼래리티별 재측정 지표** 로 해체:

| 지표 | 정의 | 목표 |
|---|---|---|
| **수록률 (Coverage)** | 1차 소스 기출 문항 중 회독 DB 에 수록된 비율 | 100% |
| **숙련도 (Mastery)** | 회독 DB 문항 중 3회독 이상 + 정답률 ≥ 90% | **≥ 95%** (★핵심 목표) |
| **재탕률 (Reappearance)** | 2차 소스에서 "이번 시험에 나왔다" 고 언급된 유형 중 1차 소스에도 존재하는 비율 | 측정만 (수험정보) |
| **Gap 해상도** | diagnose 약점 영역(직업기초 48.32%)을 기출 세부유형 단위로 분해한 수 | ≥ 10 유형 |

사용자가 원한 95% 는 **숙련도 95%** 로 재해석. 이게 실전에서 합격으로 직결되는 수치.

## 4. 시스템 설계 (exam_analyzer 확장)

```
exam_analyzer/
├── (기존 모듈들)
└── corpus/                    # 신규
    ├── __init__.py
    ├── models.py              # Question, Choice, Attempt, ReviewRound dataclasses
    ├── storage.py             # ~/.exam_corpus.json (사용자 기출 DB)
    ├── import_.py             # 알라딘 이북 발췌 반입 (수기 입력 / JSON / 텍스트)
    ├── drill.py               # 회독 모드 (플래시카드, 랜덤, 취약 유형 집중)
    ├── scoring.py             # 숙련도 계산, gap 연결
    └── match.py               # 2차 소스(후기) 키워드 ↔ 1차 소스(기출) 매핑
```

### 데이터 모델 (요지)

```python
@dataclass
class Question:
    id: str                       # sha1(book_id + q_number)[:8]
    book_id: str                  # "aladin_ebook_XXX"
    book_title: str
    publisher: str
    edition_year: int
    source_page: Optional[str]    # "p.132" 등
    area: str                     # "NCS/의사소통" | "직무/서민금융생활지원법"
    subtype: str                  # "문단배열", "조문적용" 등 세부 유형
    question_text: str            # 원문 발췌
    choices: List[Choice]         # 선지 원문 (단어 단위)
    correct_index: int            # 정답 인덱스
    explanation: str              # 해설
    related_law_articles: List[str]  # "서민금융생활지원법 §14" 등
    tags: List[str]

@dataclass
class Choice:
    index: int                    # 1..5
    text: str
    is_correct: bool
    trap_type: Optional[str]      # "수치변경", "조건누락", "유사개념" 등

@dataclass
class Attempt:
    question_id: str
    round_num: int                # 회독 차수
    attempted_at: str             # ISO datetime
    selected_index: int
    is_correct: bool
    time_spent_sec: Optional[float]
    confidence: str               # "sure" | "guess" | "eliminated"
    note: str

@dataclass
class ReviewRound:
    round_num: int
    started_at: str
    completed_at: Optional[str]
    question_ids_in_scope: List[str]
```

### 핵심 서브커맨드 (신규)

| 명령 | 용도 |
|---|---|
| `corpus import` | 이북 발췌본 반입 (JSON/대화형/텍스트 파싱) |
| `corpus list` | 수록 문항 목록 (영역/유형/책별) |
| `corpus stats` | 수록률·숙련도·유형별 정답률 |
| `drill start` | 회독 세션 시작 (범위·유형 선택) |
| `drill next` | 다음 문항 제시 |
| `drill answer` | 답안 제출·해설 표시·Attempt 기록 |
| `drill weak` | 숙련도 낮은 유형만 집중 회독 |
| `match reviews` | 2차 소스(후기 키워드) 파일을 받아 1차 corpus 와 매핑, 재탕 확률 추정 |

### diagnose 연계
`diagnose --with-corpus` 옵션 추가:
- 약점 영역(직업기초) 을 **기출 세부유형별로 분해**
- 예: "직업기초 48.32% 중, 수리/도표해석 유형 정답률 30%, 의사소통/문단배열 65%" 식
- 어느 유형에 얼마의 시간을 배분해야 하는지 수치로 권고

## 5. 다중 에이전트 아키텍처 (2차 소스 수집 한정)

**중요**: 1차 소스(알라딘 이북) 는 사용자가 직접 입력. 에이전트 불개입 (저작권·정확성).
에이전트는 **2차 소스(공개 후기) 수집·정제** 에만 사용.

```
        ┌────────┐    ┌────────┐
        │ Team A │    │ Team B │   2차 소스 독립 수집 (병렬)
        │ 후기   │    │ 후기   │
        └───┬────┘    └───┬────┘
            └──────┬─────┘
                   ▼
              ┌─────────┐
              │ Team C  │   교차검증 (A∩B vs 단일)
              └────┬────┘
                   ▼
              ┌─────────┐
              │ Team D  │   회의론자: 단일소스·구체성부족 기각
              └────┬────┘
                   ▼
              ┌─────────────┐
              │ Team E      │   1차 corpus 와 매핑
              │ (matcher)   │   "후기 키워드 X" ↔ "기출 책 Q#17"
              └────┬────────┘
                   ▼
              재탕 추정 보고서
```

### 기각 하드룰 (모든 에이전트 프롬프트 서두에 명시)
- 출처 URL + 발행일 + 직접 인용 없는 주장 → 즉시 기각
- 다른 기관/다른 회차 후기 오인 매칭 → 기각
- "일반적으로 ..." 수준의 일반론 → 기각
- Claude 상상 → **즉시 기각 + 에이전트 신뢰도 감점**
- 스니펫 제목만 있고 본문 없음 → 기각

### 신뢰도 레벨
- 🟢 교차검증 (독립 ≥2 소스 구체 언급)
- 🟡 단일 소스 (참고만)
- 🔴 상충/기각 (docs/99_rejected.md)

## 6. 진행 단계

### Phase 0: 사용자 확답 수령 (지금 블로커)
- **Q1**: 보유 알라딘 이북 목록 (제목/출판사/판본/수록문항수 추정)
- **Q2**: 이북 콘텐츠를 어떻게 반입할지 (수기 입력 / 스샷 OCR / 사용자가 텍스트 복붙)
- **Q3**: 수험번호 앞 `1056` 의 직렬 (종합직/전산/법무/ICT 등)
- **Q4**: 필기 시행일 대략 (2026-04-XX? 3월? 2월?)
- **Q5**: 저번 실패 경위 간단히 — 같은 실수 반복 방지를 위해

### Phase 1: 1차 소스 적재 (사용자 + 도구)
- `corpus import` 기능 구현
- 사용자가 이북에서 발췌한 문항 반입
- 목표: 수록률 100% (이북 내 모든 해당 영역 문항)

### Phase 2: 1차 corpus 구조 검증
- 영역·유형 분포 확인
- 중복 제거
- 정답/해설 무결성 체크

### Phase 3: 회독 도구 구현 (`drill`)
- 플래시카드 모드, 랜덤 모드, 취약 유형 집중 모드
- Attempt 기록 → 숙련도 산출

### Phase 4: 2차 소스 수집 (에이전트 A/B/C/D)
- 공개 후기 수집·검증
- 산출: 이번 시험에 재등장 주장된 키워드 리스트 (🟢/🟡)

### Phase 5: 매핑 (에이전트 E + `match`)
- 2차 소스 키워드 ↔ 1차 corpus 문항 매핑
- 산출: "이번 시험 #N번 = 책 X의 Q#M 유사" 추정표

### Phase 6: diagnose 통합
- 약점 영역 × 재탕 유형 교집합 = 최우선 회독 대상
- `diagnose --with-corpus` 서브옵션

### Phase 7: 장기 회독 운영
- 정기 drill 세션
- 회독 차수별 숙련도 변화 그래프
- 숙련도 95% 도달 시 알림

## 8. 저작권·윤리

- 1차 소스(구매 이북) 원문은 **저장소에 커밋 금지**. 홈 디렉터리 `~/.exam_corpus.json` 에만.
- 2차 소스(후기) 인용은 짧은 인용 + 원문 출처 링크 필수.
- 공개 저장소 문서에는 **메타 요약만** (예: "수리/도표 유형 12문항 수록"), 문항 본문 미노출.

## 9. 실패 방지 체크리스트 (저번 실수 반복 금지)

- [ ] 에이전트가 학습 데이터 상상으로 문항 만들지 않았는가
- [ ] 1차 소스를 2차 소스보다 우선했는가
- [ ] 각 주장의 출처·인용·날짜가 있는가
- [ ] 직렬·회차 특정 없이 일반론으로 작업하지 않았는가
- [ ] 사용자가 이해·검증 가능한 형태로 산출되었는가
- [ ] diagnose 의 약점 영역 수치와 연결되었는가
- [ ] 회독 가능한 구조인가 (한 번 만들고 끝이 아님)
