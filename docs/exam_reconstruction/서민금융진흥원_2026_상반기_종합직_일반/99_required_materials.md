# 추가 1차 자료 요청 (CLAUDE.md §1-9 의무 이행)

> 원칙: "공개 소스로 확보 불가한 부분은 **필수 자료** 로 직언한다 (CLAUDE.md §1-9)".
> 아래는 공개 웹 fetch 제약 (403/allowlist) 으로 **직접 취득 실패** 한 자료.
> 복원률 95% 북극성을 달성하려면 아래 자료 중 최소 1~3번은 사용자 협조 필수.

## 🚨 필수 (Priority 1) — 이것 없으면 R3 이후 전 단계 오염 가능

### M1. 서민금융진흥원 2026년 상반기 종합직 신규채용 공고 원문
- **필요한 이유**: 공식 공고가 시험 영역·문항수·시간·배점·직렬코드 의 **유일한 확정 팩트 소스**. 공개 웹 fetch 전부 403 차단.
- **원하는 형식**:
  - 공고 PDF 파일 (또는 HTML 복붙)
  - 모집요강 본문 (특히 "필기전형" 섹션 전체)
  - 직렬 코드표 (수험번호 앞 4자리 매핑)
- **얻을 수 있는 곳**:
  - 사용자 이메일/응시 이력 (지원 시 다운로드한 공고 PDF)
  - 서민금융진흥원 공식 홈페이지 캐시 (로그인 상태로 접근)
  - 지원서 접수처 확인증
- **제공 방식 예**: 스샷 이미지 또는 텍스트 복붙 (개인정보 마스킹 OK)

### M2. 수험번호 `1056-115716` 의 `1056` 직렬 매핑
- **필요한 이유**: 직렬 잘못 특정하면 이후 채용대행사·기출·예상문항 조사 전부 무의미.
- **현재 추정**: 종합직-일반 / 금융일반 전공. 그러나 **미확정**.
- **확인 방법**: 공고 "직렬별 모집인원·과목" 표 또는 "수험번호 부여 방식" 안내

### M3. 사용자 보유 알라딘 이북 목록
- **필요한 이유**: 1차 소스 corpus 구축의 주축. plan v3 §소스계층 에서 1차.
- **원하는 정보**:
  - 제목 / 출판사 / 판본연도 (ISBN 있으면 더 좋음)
  - 각 책 수록 기관 (예: "2024 금융 공기업 NCS 기출" 이 어디 기관 커버?)
  - 수록 문항 총수 (대략)

## ⚠ 권장 (Priority 2) — 복원률 향상 기여

### M4. 사용자 응시 당시 시험지 특징 메모
- 총 문항수 직접 카운트
- 각 영역별 문항수 인상
- 시간 배분 (어떤 영역에 몇 분 줬는지)
- 특이 기억나는 지문·키워드 (법령명·계산유형 등)
- **주의**: "기억 안 난다" 도 정답. 상상해서 적지 말 것.

### M5. 저번 알라딘 NCS 작업 실패 경위 간단 설명
- CLAUDE.md §1 의 재발 방지 목적
- 어떤 입력/과정/결과로 실패했는가

## 🛠 도구 개선 제안 (Priority 3) — 환경 제약 완화

### T1. WebFetch 대체 도구 (사용자 판단 필요)
- 현재 WebFetch 는 한국 커뮤니티 대부분 403
- 대안: **Playwright / Selenium 기반 헤드리스 브라우저** 설치 → 실제 브라우저로 렌더링
- 제약: 별도 설치·환경 검토 필요 (사용자 승인 필요)
- 비용: OSS 무료, 디스크 수백 MB

### T2. Google Scholar / KRIVET 학술 DB 접근
- WebFetch 차단 여부 아직 미확인
- 차단 안 되면 NCS 측정·공기업 출제 구조 연구 논문 접근 가능

### T3. 공공데이터포털 Open API (JSON)
- 페이지 fetch 실패해도 API 콜은 가능한 경우 많음
- 필요: API 키 (무료 발급 가능, 사용자 절차)

## 📋 사용자 제공 시 우선순위
**M1 + M2 + M3 최우선**. 이 3개만 주시면 R3/R4/R5 재개 가능.
M4 는 회독 corpus 구축 시점(R8) 에 재요청 가능.
T1/T2/T3 은 사용자 선택 사항.

## 요청 형식 제안
사용자가 채팅창에 아래 중 편한 방식으로:
- **(a)** 공고 PDF 스샷 여러 장 업로드
- **(b)** 공고 본문 텍스트 복붙 (긴 거 OK)
- **(c)** 보유 이북 목록만 간단히 타이핑 (제목-출판사-연도)
- **(d)** 현재 제공 불가한 항목은 "지금 없음" 이라 명시 → 해당 범위는 추정 신뢰도 낮음으로 기록
