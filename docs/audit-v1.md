## 4. 서브에이전트 "Plan mode 활성화" 오류 — 근본원인

### 관찰
- 메인 세션은 ExitPlanMode 호출 후 승인 완료 (plan mode OFF 확정)
- general-purpose 서브에이전트 파견 → "Plan mode 라서 실행 불가" 라고 거부
- 거부 사유로 "WebSearch/WebFetch 가 deferred 상태" 도 함께 언급

### 가설별 분석

**가설 1 — 서브에이전트가 부모 plan mode 를 상속**
- 가능성 낮음. ExitPlanMode 호출 후 명시적으로 plan mode 꺼짐.
- ⚠ 그러나 **확실하게 검증된 정보 아님**. Claude Code 문서상 subagent-parent plan mode 상속 규칙 명시 못 봤음.

**가설 2 — 서브에이전트에 WebSearch/WebFetch 도구 미로드**
- 매우 높음. 메인 세션에서 ToolSearch 로 로드한 도구는 메인에만 귀속.
- 서브에이전트는 자체적으로 ToolSearch 호출 필요.
- 내가 에이전트 프롬프트에 "ToolSearch 로 로드 먼저" 를 명시하지 않았음.

**가설 3 — 합리화**
- 에이전트가 "실행 불가" 판단 후 "plan mode" 라는 잘못된 원인에 귀속.
- 가설 2 가 실제 원인이고 가설 3 은 그 결과.

### 가장 개연성 있는 결론
**가설 2 + 3**: 도구 접근 불가 → 엉뚱한 원인 귀속.

### 재발 방지 (systemic fix)
1. 서브에이전트 파견 시 프롬프트 맨 앞에 **"먼저 ToolSearch 로 select:WebSearch,WebFetch 로드하라"** 를 명시.
2. 또는 메인 세션에서 웹 조회를 직접 수행 → 결과 텍스트를 서브에이전트에게 전달 (도구 상태 공유 불필요).
3. CLAUDE.md (신설) 에 **"Agent dispatch checklist"** 기록 → 다음 세션도 자동 준수.
4. 에이전트에게 "불가 사유를 추측하지 말고, 보유 도구 목록을 먼저 보고하라" 를 지시하도록 프롬프트 템플릿화.

## 6. 스노우볼 방지를 위한 하드 룰 (이후 모든 작업에 적용)

1. **수치는 출처 없으면 쓰지 마라.** "60-80%", "5회", "0.5배" 같은 구체 수치는 검증 가능한 출처가 있을 때만.
2. **일반 통념은 반드시 약화 표현으로.** "~이다" → "일반적으로 ~라고 알려져 있으나 기관별 편차 큼".
3. **휴리스틱은 출력 시 명시적 레이블.** "이것은 휴리스틱 권고입니다" 문구 필수.
4. **테스트에 휴리스틱 값을 박지 마라.** 수학만 회귀 방지.
5. **에이전트 파견 전 도구 세트 사전점검.** CLAUDE.md 체크리스트 강제.
6. **원본 소스 우선.** 1차 (사용자 구매 기출) > 3차 (공식 공고) > 2차 (후기). 내 학습 데이터는 소스 아님.
7. **단정조 금지.** "이 기관은 X 가 출제됩니다" → "후기 N 건에서 X 언급이 있다".
8. **자기 검증 의무.** 새 문서 작성 후 "내가 지금 출처 없이 쓴 문장 3개 찾아봐" 를 스스로 실행.
