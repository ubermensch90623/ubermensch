Here's a comprehensive analysis of `eugeniughelbur/obsidian-second-brain`.

## What it is

A **Claude Code skill** (not an Obsidian plugin) that turns an Obsidian vault into a self-evolving, AI-managed knowledge base. The vault doesn't just accumulate notes — Claude reads, rewrites, reconciles, and propagates updates across linked pages.

Author: **Eugeniu Ghelbur** · License: **MIT** · Languages: ~80% Python, ~17% Shell.

## How it's installed

It lives at `~/.claude/skills/obsidian-second-brain` and is set up via `scripts/quick-install.sh` or a manual clone + `scripts/setup.sh "/path/to/vault"`. Optional research APIs (xAI Grok, Perplexity Sonar, YouTube Data v3) are configured via `~/.config/obsidian-second-brain/.env`.

## Architecture (3 layers)

1. **Access layer** — MCP `mcp-obsidian` server (preferred) or direct filesystem ops.
2. **Vault layer** — Plain markdown with rich frontmatter, wiki-links, **bi-temporal fact tracking** (when something was true vs. when it was learned).
3. **Agent layer** — Parallel subagents per note type during complex operations (e.g. `/obsidian-save` spawns 5 subagents for People, Projects, Tasks, Ideas, etc.).

## The 31 commands, by category

- **Operations (21)** — `/obsidian-save`, `/obsidian-daily`, `/obsidian-project`, `/obsidian-person`, `/obsidian-task`, `/obsidian-log`, `/obsidian-health`, etc. Save, ingest, synthesize, reconcile, audit.
- **Thinking tools (4)** — `/obsidian-challenge` (red-team), `/obsidian-emerge` (pattern detect), `/obsidian-connect` (cross-domain bridges), `/obsidian-graduate` (idea → project spec).
- **Context (1)** — `/obsidian-world` loads identity + active state for instant continuity.
- **Research (5)** — `/x-read`, `/x-pulse`, `/research`, `/research-deep`, `/youtube`. "Vault-first" — they search local notes for gaps before hitting external APIs, and write results back with citations.

## Automation

- **Scheduled agents (cron):** Morning 8am (daily note + overdue tasks), Nightly 10pm (synthesis + reconcile), Friday 6pm (weekly review), Sunday 9pm (health audit).
- **PostCompact hook:** A headless subprocess that runs during Claude Code context compaction, silently extracting session insights into the vault — so context survives compaction.

## Imposed vault structure

```
Your Vault/
├── _CLAUDE.md       ← operating rules (overrides skill defaults)
├── Home.md          ← dashboard
├── SOUL.md          ← identity
├── Daily/           ← YYYY-MM-DD.md
├── Projects/  People/  Ideas/  Tasks/  Dev Logs/
├── Reviews/  Boards/ (kanban)  Templates/  Knowledge/
├── index.md         ← catalog
├── log.md           ← audit trail
└── CRITICAL_FACTS.md ← ~120 tokens of always-true facts
```

## Two core invariants

1. **Precedence** — `_CLAUDE.md` in the vault wins over skill defaults wherever it speaks.
2. **Propagation** — every write touches multiple pages (kanbans, daily notes, indices). Orphaned notes are treated as vault rot.

## The big idea

It extends Karpathy's "LLM Wiki" pattern with a **vault that rewrites itself**: notes get updated rather than just appended, contradictions get reconciled, patterns surface via synthesis — the vault becomes a compound asset that grows more useful as Claude writes more into it. Notes are explicitly designed for *future-Claude retrieval, not human reading* (preamble-driven, recency-marked, citation-rich).
